LEVEL 1 / SYSTEM CONTEXT / 20 SECONDS

One platform. Different responsibilities.

GIFMP4SVG2x PNG

A logical system view, not a live Azure inventory. Teaching, course authoring and administration have different responsibilities; connected services are source dependencies.

Four steps / source references
  1. 0-5s / Teacher shapes the course
    A teacher sets the course intent and reviews its materials and learning design.
  2. 5-10s / Learner takes a turn
    A learner asks, practises, or explains through the course-grounded teaching experience.
  3. 10-15s / Services support the interaction
    The platform uses managed agents, course search, and application storage.
  4. 15-20s / People inspect the result
    Learning artifacts and scoped insights return to people; outputs are not proof of mastery.

Architecture and roles · Application boundaries

LEVEL 2 / SERVICE BOUNDARIES / 20 SECONDS

Four services. Clear boundaries.

GIFMP4SVG2x PNG

Four application build units, not four Azure resources. Browser code calls the APIs. The embedded teacher dashboard uses the main API; admin access and assignments also use it. The admin analytics API requires a separately authenticated, private deployment boundary.

Four steps / source references
  1. 0-5s / Main web experience
    The main web bundle hosts learner chat, course creation, artifacts, and teacher views.
  2. 5-10s / Main application API
    The main API owns course access, teaching turns, materials, and in-process workers.
  3. 10-15s / Separate administration
    Admin analytics uses its own API through a required external access boundary.
  4. 15-20s / API-owned integrations
    The APIs call managed services directly; the admin API is not a proxy for the main API.

Deployment units and required boundaries · Admin API routing · Main application assembly

LEVEL 3 / TEACHING RUNTIME / 20 SECONDS

Inside a single teaching turn.

GIFMP4SVG2x PNG

This follows the canonical streaming path. Graph context is conditional. The harness, Foundry agent, local tools and transport adapters have separate jobs; SSE, AG-UI and A2UI are not extra teaching agents.

Four steps / source references
  1. 0-5s / Authorize the request
    Typed chat routes verify an active user and course access before the teaching turn.
  2. 5-10s / Contextualise
    Build scoped context. Show Contextualising while profile and grounding are prepared.
  3. 10-15s / Coordinate agent and tools
    The harness calls the named Foundry TA and dispatches local tool calls and results.
  4. 15-20s / Stream and reconcile
    Adapters deliver text and artifacts; the chat hook handles state, stop, errors, and persistence.

Typed chat entry points · Harness and context phases · Chat state and presentation

DATAFLOW / COURSE GROUNDING / 20 SECONDS

Materials become usable course context.

GIFMP4SVG2x PNG

The common indexing path uses Document Intelligence Layout, Azure OpenAI embeddings and Azure AI Search. Retrieval checks the course/material-session scope. TA creation, material readiness and curriculum readiness are separate states.

Four steps / source references
  1. 0-5s / Store course materials
    Teacher materials enter Blob Storage and persisted material-processing jobs.
  2. 5-10s / Extract and embed
    Document Intelligence structures the material; embeddings make chunks retrievable.
  3. 10-15s / Retrieve within course scope
    Azure AI Search holds the shared index; course/session filters constrain retrieval.
  4. 15-20s / Return grounded passages
    The teaching turn receives selected passages and source metadata for cited responses.

Material processing and dataflow · Common indexing pipeline · Scoped passage retrieval

DATAFLOW / OPT-IN MEMORY / 20 SECONDS

Evidence changes state. Not confidence.

GIFMP4SVG2x PNG

This is the custom learner-memory pipeline, not hosted conversational recall. A reviewed curriculum constrains interpretation and reduction. Shadow mode records graph state while legacy progress retains authority; authoritative mode uses the committed graph state. Rejected or pending processing preserves the last complete snapshot.

Four steps / source references
  1. 0-5s / Capture durable evidence
    Accept a scoped learner event with a durable receipt; processing happens asynchronously.
  2. 5-10s / Validate the interpretation
    Model observations need source evidence and validation; confidence does not write state.
  3. 10-15s / Apply deterministic policy
    Reviewed curriculum and accepted evidence constrain deterministic state transitions.
  4. 15-20s / Publish and inform the next turn
    Publish snapshot and history atomically; derive bounded context, gaps, and next probes.

Learner-memory contracts and modes · Feature and worker defaults · Validated reduction and atomic publication
