REPRODUCIBLE AND SAFE BY CONSTRUCTION

Record the app, not an imitation.

Read the complete generation guide for the capture pipeline, exact preferences/memory regeneration commands, output locations, safety boundaries and validation checklist.

Playwright drives real clicks, typing, navigation and asset controls in the unchanged React application. Local API fixtures supply a synthetic lesson and learner data. Browser screenshots are captured at each step and FFmpeg encodes them as MP4 and looping GIF, adding a pointer, captions and a lavender title bar. The old top-right badge has been removed; fixture provenance is described here rather than stamped over the video.

Course welcome screens show four conversation starters. Before opening any document, quiz, challenge, slide deck or circuit, the recorder collapses the native left navigation. Both presentation rules are asserted during capture. Fresh browser storage contains only synthetic identities; unknown API calls fail and external services are blocked. Frames are paced for readability, not to measure model latency.

The side-by-side workflow runs two isolated browser contexts concurrently, one learner and one teacher. The teacher selects the learner in Insights and asks for activity updates. The recorded Insights replies are constructed from that learner's intercepted question and submitted quiz receipt, so the sequence verifies a change from zero to one submitted check. It is not represented as live cloud inference or automatic monitoring of real students.

The learner-memory video targets the project's custom memory structure, not the separate hosted Memory Store. It opens the actual Graph Memory panel, submits a diagnostic with a frozen assessment identity, shows a pending receipt without replacing the old snapshot, then displays a simulated committed update and the learner's own quoted reasoning. The profile recommends another independent probe rather than automatically declaring mastery. Memory is opt-in in the product; this local demo does not enable a real course or run a live reducer/worker.

The onboarding demo starts with a synthetic signed-in account that has not completed setup. It records profile details, saves them through the actual form and verifies a later Settings update. The teacher demos use the embedded dashboard in the main app. The administrator demos run the independent Admin Dashboard frontend with an isolated fictional institution and directory; any access-management changes remain in the recording's in-memory fixture.

Regenerate the actual-interface tutorials

Install the isolated media dependencies from the repository root:

npm --prefix assets\web\motion ci

In another PowerShell terminal, start the normal frontend in an isolated test mode:

$env:VITE_API_BASE_URL = "http://127.0.0.1:4188"
$env:VITE_API_URL = "http://127.0.0.1:4188"
$env:VITE_DASHBOARD_API_URL = "http://127.0.0.1:4188"
$env:VITE_USE_AGUI = "false"
npm --prefix "Agentic Shiksha Platform\Frontend" run dev -- --host 127.0.0.1 --port 4188 --strictPort --mode test

For the two admin recordings, start the separate admin frontend in another terminal:

$env:VITE_API_BASE_URL = "http://127.0.0.1:4190"
$env:VITE_API_URL = "http://127.0.0.1:4190"
$env:VITE_DASHBOARD_API_URL = "http://127.0.0.1:4190"
$env:VITE_STUDENT_ASSIGNMENTS_ENABLED = "true"
npm --prefix "Admin-Dashboard\frontend" run dev -- --host 127.0.0.1 --port 4190 --strictPort --mode test

Then run the recorder from the repository root:

npm --prefix assets\web\motion run record-platform -- --all
node assets\web\motion\generate.mjs --stills-only

Use --demo "onboarding-profile,teacher-roster,teacher-usage,admin-overview,admin-assignments" for the five new demos, or --all for all sixteen. Existing selectors learner,teacher,answer-depth,documents,preferences,companion-review,slides,circuits,challenges,student-teacher,memory remain supported. Add --check-flow to exercise controls without encoding. TUTORIAL_BASE_URL and TUTORIAL_ADMIN_BASE_URL accept only localhost HTTP origins. Both apps require their existing dependencies; the recordings use no API keys or live backend.

Formats and editing

Single-screen recordings are 1360 x 928; the side-by-side recording is 2656 x 976. GIFs run at 10 fps and H.264 MP4s at 12 fps, with PNG stills, VTT captions and timing metadata. Use full screen for the detailed paired view. These captures are raster media, not editable UI vectors. Research illustrations remain editable SVGs. Raw GIFs cannot provide an embedded pause button.

Edit platform-demo.mjs for common fixtures and record-platform.mjs for capture. New recipes are onboarding-demo.mjs, teacher-dashboard-demos.mjs and admin-dashboard-demos.mjs. The media generator publishes both sixteen-video galleries from verified recording metadata; use --stills-only to skip re-encoding the conceptual flow.

The video-only ZIP includes all sixteen MP4/GIF files, stills, captions, metadata and an offline gallery. The full ZIP preserves the current web and images layout. Source references and regeneration require the repository. Both bundles exclude dependencies and real user data.
